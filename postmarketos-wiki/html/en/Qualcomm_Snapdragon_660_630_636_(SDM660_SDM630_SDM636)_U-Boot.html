U-Boot

There is a fork of U-Boot with pathset specific to support using is as secondary bootloader (chainloaded from previous bootloader stage, ABL) for SDM630/636/660 devices. The fork is maintained at https://github.com/sdm660-mainline/u-boot. It contains very few patches (~30) on top of mainline U-Boot, and half of those are devices' DTS for devices that are not upstream, and few drivers and small fixes that are on the way to upstream U-Boot (slowly).

Features

Since recent rebase on upstream release v2026.07, it fully supports everything that is needed to boot linux, and postmarketOS, on android-based phones and tablets:

  • Clocks / pinctrl / GPIOs
  • Display (simplefb)
  • Buttons
  • Booting from eMMC, SD card
  • USB, including:
    • fastboot mode
    • serial gadget mode for to use U-Boot console
    • USB and mass storage mode (UMS) to expose eMMC/SD contents as external USB disk
    • separate UMS mode for pmOS subpartitions on userdata partition
  • EFI booting, including booting from pmOS-style subpartitions on userdata partition
  • extlinux boot, if one desires to use it
  • android boot images support to boot Android

Building instructions

For now just see how CI does it: https://github.com/sdm660-mainline/u-boot/blob/master-sdm660/.github/workflows/build-uboot.yml .

Also make sure you have the necessary tools and build dependencies, once again, look at our infra scripts used for CI runners for reference: https://github.com/sdm660-mainline/infra/blob/main/docker-github-runner/Dockerfile.x64#L8

In short, the process is similar to how mainline u-boot is built, but using our specific defconfig + fragments.

  • first, create build directory:
mkdir -p output
  • for devices that are upstream (xiaomi-lavender, sony-pioneer):
make CROSS_COMPILE=aarch64-linux-gnu- O=.output qcom_defconfig qcom-sdm660-phone.config
  • for devices that are not upstream:
make CROSS_COMPILE=aarch64-linux-gnu- O=.output qcom_defconfig qcom-sdm660-phone.config qcom-downstream.config

This will produce u-boot binaries, but then you must pack it into boot.img suitable for your device using mkbootimg tool.

Once again look how our CI does it: https://github.com/sdm660-mainline/u-boot/blob/master-sdm660/.ci/bootimg-all.sh

In short, use gzipped u-boot-nodtb.bin, append it with dtb for your device, use it as --kernel argument for mkbootimg. Example: 

gzip -c -9 u-boot-nodtb.bin > u-boot-nodtb.bin.gz
cat u-boot-nodtb.bin.gz ./arch/arm/dts/qcom/sdm636-xiaomi-whyred.dtb > u-boot-nodtb.bin.gz-dtb
mkbootimg --kernel u-boot-nodtb.bin.gz-dtb --ramdisk initramfs-empty.gz ...

Flashing instructions

Get the boot image for your device from GitHub Releases page or build it yourself using instructions above. Flash into your phone/tablet boot partition using fastboot mode 

fastboot flash boot boot-uboot-vendor-codename.img

Usage instructions

If you don't press any button during boot, u-boot will execute its normal boot flow (bootflow scan -lb), which will find and boot first available boot method, in order

  • UEFI booting from first available partition (including subpartitions on userdata)
  • extlinux boot from SD card, then from eMMC

During boot, if you hold Volume Down button once you see U-Boot logo on the screen, u-boot will boot into fastboot mode. In this mode you can use most normal fastboot commands, flashing will write to eMMC. To execute any u-boot command, you can use 

fastboot oem 'run:<any uboot command>'

Which is the easiest way to use u-boot console not requiring any additional tools other than fastboot. Disadvantage is that you have to see commands output only on phone's screen. That's why it is much better to use USB Serial Gadget mode.

If you hold Volume Up button instead, you will have access to boot menu with many useful options. You can choose where to boot from, or use serial gadget / usb mass storage mode. Or dump some phone specific info, like kernel cmdline from previous bootloader or speedbin/fuses values.
