From postmarketOS Wiki

This guide explains how to recycle an old phone into a minimal, optionally headless server over Wi-Fi, similar to a Raspberry Pi. Other devices with different form factors may also work.

Preparation

  • A router (preferably running OpenWrt)
  • A postmarketOS phone with Wi-Fi capability (preferably running OpenRC, wpa_supplicant and buffyboard)

While systemd can be used as the init system, this guide assumes OpenRC, as it is more lightweight. If the touchscreen works, choose buffyboard as the UI. If it does not work but USB networking does, select console instead.

Initial setup

These must be done directly on the phone using a TTY or USB networking.

Configure Wi-Fi

$ wpa_passphrase "SSID_NAME" "PASSWORD" | doas tee /etc/wpa_supplicant/wpa_supplicant.conf
$ doas chmod 600 /etc/wpa_supplicant/wpa_supplicant.conf

Get initial Wi-Fi access via DHCP

$ doas ip link set wlan0 up
$ doas wpa_supplicant -B -i wlan0 -c /etc/wpa_supplicant/wpa_supplicant.conf
$ doas udhcpc -i wlan0

Make networking persistent

Now SSH into the device and make the configuration persistent.

Disable MAC address randomization

$ sudo vi /etc/wpa_supplicant/wpa_supplicant.conf

Add the following at the top of the file: 

mac_addr=0

Configure static IP

A static IP is recommended, as servers generally have a consistent IP address. Adjust the configuration if necessary. 

$ doas vi /etc/network/interfaces

Replace the file with the following content: 

auto lo
iface lo inet loopback

auto wlan0
iface wlan0 inet static
    address 192.168.1.50
    netmask 255.255.255.0
    gateway 192.168.1.1

Configure DNS

$ doas vi /etc/resolv.conf

Replace the file with the following content: 

search lan
nameserver 192.168.1.1

Enable the required services

$ doas rc-update add networking default
$ doas rc-update add wpa_supplicant default

Optional steps

Make the server headless

WARNING: Do not run this unless SSH access is confirmed to be working.

The screen can be blanked to create a headless effect and save battery power. You will have to perform the following steps after reboot. 

$ TERM=linux doas setterm --blank force < /dev/tty1

Press Enter until the text on the console disappears, then stop buffyboard: 

$ doas rc-service buffyboard stop

Troubleshooting

Wi-Fi does not work

You may need to perform the following steps after reboot. 

$ doas rc-service networking restart
$ doas rc-service wpa_supplicant restart

Connection fails after some time

Sometimes, suspend can cause the Wi-Fi connection to drop, which may break SSH and other services. For a server, it is assumed the device is always plugged in, so automatic suspend is undesirable. To prevent it, recompile the kernel using envkernel.sh, leaving the following options unset, and sideload the resulting kernel package. 

# CONFIG_CPU_IDLE is not set
# CONFIG_SUSPEND is not set
# CONFIG_HIBERNATION is not set
# CONFIG_PM_SLEEP is not set
