From postmarketOS Wiki

Sometimes while mainlining, components do not work and you do not know why. You can try reading the Android kernel sources to understand what it is doing but often times it is easier to add a few printk statements and figure out what Android is doing at runtime.

Building the Kernel

One option to do this is Building the kernel with Androids build system but that method requires installing a lot of Android build tools will use up hundereds of Gigabytes of disk space.

Building the kernel using postmarketOS's envkernel infrastructure may be easier since it doesn't require you to install any extra programs. However you might have to patch the kernel to get it to compile. Look at Compiling kernels with envkernel.sh how to do so.

Troubleshooting downstream kernel compilation might have relevant information on how to get your kernel to compile. Usually if the functionality is not relevant to what you want to test you can comment out the code that fails to compile.

Booting Android with your custom kernel

Obtaining boot.img

For LineageOS this is easy as they have it on the download page next to the recovery zip.

For other Androids, find out the currently active boot slot by rebooting to the bootloader and running fastboot getvar current-slot. Then reboot into the recovery, enable ADB and run adb pull /dev/block/by-name/boot_{current slot} boot.img

Repackaging boot.img

Take note of the parameters this command spits out.
$ unpack_bootimg --boot_img boot.img --format mkbootimg

Run file to find out compression of the kernel.
$ file out/kernel

Copy in our patched kernel.
Path will be different if you built it with the Android build system.
There may already be an compressed version called Image.{gz,lz,xz} you can use so you don't need to compress yourself.
$ cp <path to downstream kernel>/.output/arch/arm64/boot/Image out/patched_kernel

Now compress your kernel image to match the one that was in the boot.img.
Example for xz:
$ xz -k patched_kernel

Then re-pack your bootimg with the parameters that unpack_bootimg gave you.
Make sure to change the --kernel parameter to point to the patched kernel.
$ mkbootimg <insert params here> -o new_boot.img

$ fastboot flash boot new_boot.img
$ fastboot reboot

Getting logs on Android

After the reboot, enable Developer Options on Android (by going into Settings -> System Information and tapping on Build number 7 times). Then enable ADB debugging and rooted ADB debugging in the developer options. 

$ adb root
$ adb shell

Now you can run uname -a and confirm that the date matches the date you built the kernel so you know that you are running your kernel. Yay!

To get logs you do either dmesg or logcat -b system.
